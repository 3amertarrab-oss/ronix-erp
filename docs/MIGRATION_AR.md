# خطة نقل البيانات — قبل الاستيراد

هذه الخطة لا تستورد أو تدمج مبالغ أو تعدّل بيانات حالية.

1. يحدد المالك أحدث تصدير JSON من الحسابات، وأحدث باك أب من البرنامج الأساسي، وأي
   مسودات JSON من محرر العقود. ملفات HTML هي البرنامج وليست نسخة مضمونة من بيانات
   المتصفح أو حساب Supabase.
2. نحفظ النسخ الأصلية خارج قاعدة التشغيل، ونثبت SHA-256 وحجم وتاريخ كل ملف. رموز
   دخول R42 موجودة بملف الحسابات المنفصل وقد لا يتضمنها باك أب بيانات المشروع.
3. نفحص بنية الملفات، وتكرار المعرّفات، والعملات، ومرفقات الصور والسندات. يُستخدم
   `scripts/migration-check.cjs` أو «فحص نسخة بيانات» من حساب المالك للفحص فقط.
4. نستعيد نسخة R42 في قاعدة تجريبية منفصلة، ثم نفحص نسخة الحسابات بواسطة قواعد
   V20 الأصلية. لا تُستبدل قاعدة العمل الحالية، ولا يُنفذ استيراد من ملف مجهول المصدر.
5. نراجع تطابق أكواد المشروعات والعملاء. التطابق بالاسم وحده لا يكفي. الأكواد المتطابقة
   تظهر مرشحات للمراجعة، ولا تُربط تلقائيًا قبل فحص العميل والسجلات.
6. نقارن العقود، والمطالبات، والمقبوضات، وتخصيص القبض، والمقدمات، ومستحقات المصممين،
   ودفعاتهم، وفروق الصرف، والأرصدة الافتتاحية. لا تُجمع قيمة الرصيد من النظامين.
7. نحدد لكل حركة تاريخية مصدرها المعتمد، ونحتفظ بمعرّفها ومرجعها. الربط لا يصدر مطالبة
   جديدة مقابل مطالبة موجودة، ولا ينشئ قبضًا جديدًا مقابل قبض مسجل سابقًا.
8. نراجع المستندات: مسودة أم معتمدة، عملتها، وقيمتها وجدول دفعاتها، وربطها بالمشروع.
   أي اختلاف يحتاج قرارًا موثقًا؛ لا تُعدل نسخة عقد سبق إصدارها لتطابق الأرقام صامتًا.
9. نجرب دورة عمل جديدة، ونقارن القوائم قبل النقل وبعده، ونتحقق من المرفقات والاستعادة.
10. بعد اعتماد النتائج يُحدد موعد النقل، وتؤخذ نسخة نهائية، ويُوقف التعديل مؤقتًا على
    النسخة القديمة، ثم تُنقل البيانات ويُحتفظ بمسار رجوع واضح.

المطلوب حاليًا: تحديد أحدث نسخة بيانات معتمدة وإتاحتها للفحص. الباك أب الموجود داخل
الحزمة المرفقة لا يُعتبر الأحدث بمجرد وجوده.
