# CRM RONIX

فرع Cloudflare المستقل يستخدم Workers + D1 + R2 ليظل التطبيق متاحًا عندما يكون الكمبيوتر مغلقًا. تعليمات النشر موجودة في [cloudflare/DEPLOY.md](cloudflare/DEPLOY.md).

تطبيق مستقل لإدارة العملاء والمشروعات، يجمع R42.3.9.34 للتشغيل والمشروعات، وV20.2 للحسابات، و1007 للعقود والعروض.
ملفات عرض السعر القديمة في جذر المستودع محفوظة. التطبيق الموحّد يعمل من `erp/server.js`.

## التشغيل

يلزم Node.js 22 أو أحدث. لا توجد حزم npm خارجية تحتاج إلى تثبيت.

```bash
cd /workspace/ronix-erp
npm start
```

الخادم يستخدم المنفذ 8788 محليًا. أول تشغيل ينشئ قاعدة فارغة؛ رابط إعداد المالك يظهر
في طرفية المشغّل. رابط الإعداد خاص بالمسؤول ولا يُرسل للموظفين. لا يُستورد الباك أب
المرفق بحزمة R42 تلقائيًا، ولا تُستخدم كلمات مرور افتراضية.

لتحديد مكان البيانات: اضبط `RONIX_DATA_DIR` على مجلد دائم خارج ملفات الموقع.
الحفظ مركزي على خادم Node نفسه، والمزامنة بين المتصفحات دورية؛ لا يلزم دخول Supabase
ثانٍ للوحدات المدمجة. تشغيل البرنامج بهذا الأمر لا ينشر رابطًا عامًا.

## ما تم ربطه

- جلسة الدخول والصلاحيات، مع منع الوصول المباشر للأقسام غير المصرح بها.
- الحسابات الأصلية V20.2 ومعادلاتها وقوالبها؛ استُبدلت طبقة التخزين والمزامنة السحابية
  المنفصلة بمزامنة الخادم المشترك، مع إبقاء المصالحة وسجل التغييرات الأصليين.
- محرر 1007، وقائمة مستندات متعددة، وربط المشروع والعميل، وحفظ المسودات واعتمادها.
- إنشاء نسخة عقد مستقلة من العرض. المستند المعتمد ثابت، وتبقى نسخته كاملة محفوظة.
- مرجع المستند المعتمد يدخل نطاق العمل في R42 ويمكن اختياره لأمر تشغيل؛ الاعتماد
  لا يصدر أمر تشغيل أو مطالبة أو قبض تلقائيًا.
- إرسال العقد للحسابات بإجراء مستقل ومنع التكرار. العملات الأجنبية تحتاج سعر تسجيل
  صريحًا بالجنيه؛ لا يُفترض سعر صرف.
- ربط مشروع مالي موجود بمشروع تشغيلي، وتحديث الاسم والعميل في المعاملة نفسها عند
  تعديل السجلات المرتبطة. النسخ التاريخية للمستندات تبقى كما صدرت.
- ملخص الحسابات للمشروع المرتبط يأتي من V20.2. التسجيل المالي لهذا المشروع يتم من
  الحسابات المعتمدة؛ مسار القبض والمطالبات القديم لا ينشئ حركة ثانية عليه.
- نسخة الخادم الاحتياطية تضم بيانات الوحدات الموحّدة داخل `extensions.unified`.

## الفحص

```bash
npm test
python3 tests/browser-smoke.py
npm run migration:check -- --input /path/to/backup.json
```

اختبار المتصفح يحتاج Python وPlaywright وChromium في `/usr/bin/chromium`؛ هذه الأدوات
متاحة في البيئة الحالية. تستخدم الاختبارات مجلدات مؤقتة وبيانات تجريبية فقط.
الاختبارات لا تُعد اعتمادًا محاسبيًا لبياناتك الفعلية.

## الرابط المشترك

راجع [تعليمات النشر](deploy/README_AR.md). النسخة تحتاج خادمًا دائمًا وHTTPS ونسخًا
احتياطية خارج الخادم قبل استخدامها كرابط عمل مشترك. لم تُنشر هذه النسخة على الإنترنت.

## حدود يجب مراجعتها

البيانات المالية التاريخية في R42 وV20 ليست قاعدتين يمكن جمع مبالغهما آليًا. وجود
حركات قديمة يمنع الإقفال الآلي إلى أن تُطابق؛ الربط لا يزيلها ولا يضيفها مرة ثانية.
تقارير R42 القديمة الخاصة بالموردين والتكلفة تبقى تقارير لقسم التشغيل، وليست بديلًا
لقوائم V20 المالية؛ القوائم المحاسبية النهائية تصدر من الحسابات المعتمدة.
أي مرفقات سحابية في النسخة المراد نقلها تحتاج التحقق من وجود الملفات نفسها، وليس
الاكتفاء بروابط أو مراجع داخل JSON.
