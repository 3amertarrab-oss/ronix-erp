# تشغيل RONIX برابط مشترك

هذه حزمة إعداد قابلة للمراجعة؛ لم تُطبّق على استضافة حقيقية.

استخدم خادم Linux يدعم Node.js 22+، وقرصًا دائمًا، واسم نطاق مع HTTPS عبر وكيل عكسي
مثل Caddy أو Nginx. يلزم تشغيل نسخة خادم واحدة فقط أمام مجلد البيانات؛ هذه النسخة
لا تستخدم قاعدة موزعة ولا تدعم عدة نسخ Node تكتب إلى المجلد نفسه.

1. ضع ملفات التطبيق خارج المجلد العام للويب. يشغل Node الملفات الموجودة تحت
   `erp/site` فقط؛ لا تعرض `erp/data` أو مجلد النسخ الاحتياطية من خادم ملفات آخر.
2. حدد مجلد بيانات دائمًا يملكه مستخدم الخدمة، بصلاحيات مقتصرة عليه، وحدد مسار
   `RONIX_INITIAL_BACKUP` للملف النظيف أو للنسخة التي سبق فحصها واعتمادها.
3. أجرِ الإعداد الأول محليًا على الخادم أو من خلال نفق SSH محلي. احتفظ برابط الإعداد
   لدى المسؤول. غيّر كلمات المرور القديمة القصيرة قبل فتح الرابط العام.
4. اضبط `RONIX_PUBLIC_MODE=1`. هذا الوضع يتطلب 12 إلى 128 محرفًا لكلمات المرور
   الجديدة ويرفض الدخول بالرموز القصيرة، ويستخدم ملفات تعريف ارتباط Secure.
5. أبقِ Node على `127.0.0.1:8788`، واجعل الوكيل العكسي يمرر اسم المضيف الأصلي
   ويدعم رفع ملفات بحجم التطبيق، بحد لا يتجاوز 24 MB لطلبات بيانات الوحدات.
   ضع HTTPS أمامه. وضع النشر العام لا يُستخدم عبر HTTP غير المشفر.
6. شغل الخدمة تلقائيًا بعد إعادة التشغيل. ملف الخدمة المثال يحتاج تعديل المسارات
   ومستخدم الخدمة قبل تثبيته. لا توجد أسرار داخل ملفات هذا المجلد.
7. انسخ مجلد البيانات كاملًا إلى تخزين منفصل بانتظام، مع اختبار الاستعادة. يحتفظ
   التطبيق أيضًا بلقطات معاملات، لكنها لا تغني عن النسخ خارج الخادم.
8. اختبر دخول المالك والمحاسب والمهندس، والصلاحيات، والحفظ بين جهازين، والتعارض،
   والطباعة، والنسخ الاحتياطي والاستعادة عبر الرابط الفعلي قبل نقل العمل إليه.

مثال إعداد Caddy بعد استبدال النطاق:

```caddyfile
ronix.example.com {
    reverse_proxy 127.0.0.1:8788
}
```

لم تُختبر هذه الإعدادات على استضافة المستخدم بعد. اختيار الاستضافة والنطاق والبيانات
النهائية هو الخطوة المتبقية قبل النشر الحقيقي.
